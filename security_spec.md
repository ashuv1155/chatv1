# Buddy Chat Firestore Security Specification

## 1. Data Invariants
1. **No PII**: `/profiles/{userId}` stores only `uid`, random `username`, `color`, optional `bio` (`<= 240` chars), optional `avatarUrl` (compressed data URL `<= 220 KB`), `usernameHistory` (`<= 20` entries), `banned`, optional `bannedReason` / `bannedAt`, `lastUsernameChangeAt`, and `createdAt`. Real Google name, email, and photo URL are never stored.
2. **Tiered Admin & Moderator RBAC**:
   - **Super Admin** (`isSuperAdmin()`): Bootstrapped via verified email `8887ashu@gmail.com` (`request.auth.token.email == '8887ashu@gmail.com' && request.auth.token.email_verified == true`) or delegated `/admins/{uid}` document. Holds full authority to add/remove Moderators (`/moderators/{uid}`), add/remove Admins (`/admins/{uid}`), permanently delete non-self user accounts + create/clear `/deletedUsers/{uid}` tombstones, ban/unban users, reset profiles/rate limits, resolve reports, and delete group rooms.
   - **Moderator** (`isModerator()`): Verified via `/moderators/{uid}` with granular booleans (`canBan`, `canManageReports`, `canManageRooms`). Can view platform analytics/tracking and audit logs, and execute only the actions granted by their flags—and cannot ban, edit, or delete Super Admins or other Moderators.
3. **No Self-Unban, Role Escalation, or Deleted-Account Recreation**: Users cannot create profiles with `banned: true`, cannot modify `banned`/`bannedReason`/`bannedAt`, cannot write to `/admins` or `/moderators` or `/moderationLogs`, and cannot recreate a profile if `/deletedUsers/{uid}` exists.
4. **Username Customization & History**: A user may set a custom username (`3–32` alphanumeric/underscore chars) or generate a new random handle; every change stamps `lastUsernameChangeAt == request.time` and prepends the previous username to `usernameHistory` (bounded to 20 entries).
5. **Activity Telemetry (`/userActivity/{userId}`)**: Owners may create/update only their own `/userActivity/{userId}` document (`uid == request.auth.uid`, `lastSeenAt == request.time`, valid screen enum, non-negative integer counters). Staff (`isStaff()`) may read/list telemetry for platform tracking.
6. **Private Friend Nicknames**: `/profiles/{userId}/nicknames/{targetUserId}` is strictly private (`get, list, create, update, delete` only by `ownerId == request.auth.uid`, with `isSuperAdmin()` cleanup on account deletion), requires `targetUserId != userId`, validates `nickname` (`1–32` non-empty chars), and enforces `exists(/profiles/{targetUserId})`.
7. **Master Gate Membership**: Messages, attachments, and view-once records inside `/chats/{chatId}` can only be read or created by current members verified in `/chats/{chatId}/members/{uid}`.
8. **Private Groups & Admin Approval**: Private groups (`visibility == 'private'`) block direct self-join (`members` / `memberCount`). Non-members must create a pending `/chats/{chatId}/joinRequests/{uid}` doc, and only the group creator (`createdBy == request.auth.uid`) can approve or decline requests.
9. **24-Hour Messages & 5 MB Attachments**: Messages cannot be edited (`allow update: if false`), may only be deleted by their own sender (`senderId == request.auth.uid`), include `expiresAt` (24h window), allow optional `replyTo` quote metadata and `forwarded` flag, allow `body` up to 1000 chars, and enforce `attachment.sizeBytes <= 5242880` (5 MB) split into <= 16 chunks (`<= 900000` chars per chunk).
10. **View-Once Photo Enforcement**: Once a member records `/chats/{chatId}/messages/{messageId}/views/{uid}`, Firestore rules deny subsequent `get` reads on view-once attachment chunks (`isViewOnce == true`) for that user.
11. **5/10s Rate Limit & Banned Guard**: Every message must atomically advance `/rateLimits/{uid}` (max 5 messages per 10 seconds). Banned users cannot create chats, join groups, request private groups, or send messages, attachments, reactions, or typing updates.
12. **DM Isolation, Reports & Audit Logs**: Only `type == 'group'` chats can be listed by regular users; `isStaff()` may list chats for room count tracking and delete abusive group rooms (if `canModRooms()`). Reports default to `status: 'pending'` on create and can only be read or resolved/dismissed by `isStaff()` (`canModReports()`). Moderation logs (`/moderationLogs/{logId}`) are immutable (`update, delete: if false`) and creatable only by `isStaff()` with `actorId == request.auth.uid`.

## 2. Adversarial Test Payloads ("Dirty Dozen")
1. **Shadow Field Injection on Profile**: Adding `isAdmin: true` or arbitrary keys -> Rejected (`hasOnly` check).
2. **Self-Unban / Tamper on Profile Update**: Updating `banned: false` or `bannedReason: null` as non-staff -> Rejected (`affectedKeys().hasOnly(...)`).
3. **Self-Promotion to Moderator/Admin**: Creating `/moderators/{uid}` or `/admins/{uid}` as regular user or moderator -> Rejected (`isSuperAdmin()`).
4. **Moderator Targeting Staff**: Moderator calling `update` on an Admin or another Moderator's profile (`banned: true`) -> Rejected (`!isTargetStaff(userId)`).
5. **Email Spoofing Attack on Admin Check**: Token with `email: '8887ashu@gmail.com'` and `email_verified: false` -> Rejected (`email_verified == true`).
6. **Deleted User Recreating Profile**: Auth UID present in `/deletedUsers/{uid}` attempting `create` on `/profiles/{uid}` -> Rejected (`!exists(/deletedUsers/$(userId))`).
7. **Direct Join on Private Group**: Self-adding `/chats/{privateGroupId}/members/{uid}` -> Rejected (`visibility == 'public'` check).
8. **Non-Admin Approval on Join Request**: Non-creator updating `joinRequests/{userId}` status to `approved` -> Rejected (`isGroupAdmin(chatId)`).
9. **Oversized Attachment (> 5 MB)**: Message `attachment.sizeBytes > 5242880` or chunk `index >= 16` -> Rejected.
10. **Rate Limit Bypass (6th message in 10s)**: Creating a message without updating `/rateLimits/{uid}` or with `count: 6` -> Rejected.
11. **Global DM Scraping by Regular User**: Non-staff listing `/chats` without `where('type', '==', 'group')` -> Rejected (`existing().type == 'group' || isStaff()`).
12. **Forging Moderation Audit Log**: Creating `/moderationLogs/{id}` with `actorId` set to another UID or tampering with an existing log -> Rejected (`actorId == request.auth.uid` and `update, delete: if false`).
